2. Demand score (0–100)
Estimates audience demand for an artist in a given city using only platform signals and search interest.
demand_score =
    platform_size_score    x 0.35
  + momentum_score         x 0.35
  + google_trends_score    x 0.20
  + city_affinity_score    x 0.10

Platform size score detail
Weighted average of normalised per-platform scores. Weights reflect commercial relevance for live events:
platform_size_score =
    normalize(monthlyStreams)    x 0.40   // Spotify — strongest purchase-intent signal
  + normalize(followers.youtube) x 0.25   // YouTube — reach
  + normalize(followers.instagram) x 0.25 // Instagram — cultural relevance
  + normalize(followers.facebook)  x 0.10 // Facebook — supplementary
normalize(x) = (x − min) / (max − min) across all artists in your DB. Output: 0.0 – 1.0, then × 100.
Note: RoG fields (rog.*) are used in momentum_score via cross_platform_score, not duplicated here. Avoid double-counting growth signals.
3. City affinity score
Measures how strong the demand environment is in a given city — independent of the artist. Based on city tier, population, and market activity.
city_affinity_score = city_tier_factor x market_activity_index x 100
market_activity_index = normalize(concerts_in_city_last_12m, 0–1)
                        // from concerts.city + concerts.date

Note: market_activity_index uses concert count in that city over the last 12 months from your concerts table — it measures how active the live market is in that city, not sellthrough.
4. Revenue prediction
Predicts gross revenue using demand score, venue capacity, and average ticket price. No sellthrough history required.
predicted_sellthrough = (demand_score / 100) x city_tier_factor
predicted_tickets     = capacity x predicted_sellthrough
avg_ticket_price      = AVG(concerts.avgTicketPrice) for artist
                        // fallback: city-level avg if artist has no past concerts
gross_revenue         = predicted_tickets x avg_ticket_price
Note: avgTicketPrice from past concerts is used only as a price reference, not as a performance signal. If the artist has zero past concerts, use the median avgTicketPrice across all artists in the same genre/category.

7. Revised popularity score
Replaces the static entropy-weighted score. No ticket data dependency.
popularity_score =
    base_entropy_score   x 0.60   // useMadPopularity — unchanged
  + momentum_score       x 0.20   // cross_platform_score / 100 from useMadGrowth
  + google_trends_score  x 0.20   // pytrends, normalised 0–1
Note: google_trends_score is relative within a query batch. Normalise all artists in a single pytrends batch call so scores are comparable. Refresh every 7 days via scheduler.
